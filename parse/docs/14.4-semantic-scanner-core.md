# Semantic Scanner Core Architecture

## Overview
The Semantic Scanner processes the stream of provisional tokens from `scan0`. Its purpose is to resolve ambiguities that `scan0` cannot, specifically emphasis pairing, link/image resolution, and block structure finalization.

## Core Responsibilities
- **Text Coalescing**: Adjacent `InlineText` tokens are merged to reduce allocations.
- **Emphasis Resolution**: Implements the stack-based emphasis pairing logic.
- **Link/Image Pairing**: Matches brackets and parentheses to resolve label and destination.
- **Heading Depth**: Finalizes the semantic meaning of ATX and Setext headings.
- **Structural Integrity**: Validates reparse points and error recovery states.

## Data Structures
- **Token Stack**: Used for pairing open/close markers.
- **Accumulator**: Merges text tokens before materialization.

## Algorithms
1.  **Emphasis Pairing**:
    - Push opening `*` or `_` delimiters onto a stack.
    - Match closing delimiters with the most recent compatible opener.
    - Convert delimiter tokens to `EmphasisOpen`, `StrongOpen`, etc.
2.  **Link Labeling**:
    - When `]` is encountered, look for the most recent matching `[`.
    - If a matching `(` follows, parse the link destination and title.
3.  **Entity Resolution**: Materialize hex/dec/named entities into characters.

## zero-allocation constraint
The semantic phase should operate over the numeric token stream as much as possible, only materializing strings for the final consumer output or when resolving complex entities.
